# Mobile 本机原生 API 与统一连接配置

## 目标

手机与桌面复用同一个执行实例和会话。所有连接模式共用一个 Web 端口、一套访问口令和一个二维码，手机业务前端沿用原有接口。

## 最终方案

- 本机原生 API 通过桌面的 AppServerManager RPC 发业务请求，CDP 用于取得句柄和接收宿主通知。
- 原生模式保留桌面已有远程主机目录，其他机器继续经桌面现有 SSH 或 Remote Control 路由访问。
- 本机原生 API 与官方云端 Remote Control 中继接入分别核对，当前产品不提供独立云端客户端授权流程。
- 连接配置支持共享 Desktop、原生 API、托管 app-server、外部 app-server。只显示并校验当前模式需要的后端字段。
- 新增 config.apply，应用时切换实际后端，保留空口令对应的现有凭据，失败恢复原服务。配置保存失败时保留运行中的连接。
- 兼容旧 remote-control/local 配置为 native，拒绝将旧非本机目标静默迁移到当前电脑。
- 合并连接和设置页面，移除空的审批与日志区域和顶部介绍。二维码默认展开。
- 宿主外壳提供小返回图标、居中插件名称，以及插件页强制重启 ChatGPT 按钮。

## 验证

- 模式切换、统一入口、失败回滚、托管进程迟到退出、配置保存失败有运行时回归。
- 配置页验证条件字段、单一二维码、单一 Web 端口和应用后的实际状态。
- 宿主与插件均通过类型检查，独立插件包通过加载检查。
- 本机安装已通过签名和隔离配置启动检查。实际运行 native 模式，Web 端口19877，口令与既有网页保持一致。
- 实际读取本机项目、会话列表和历史成功。其他机器恢复4台目录，远程 macmini 读取8个项目成功。
- Dots 增补 Rspack 服务发现后，身份检查和主 Dots 接口返回成功，保留旧版映射、原生请求头及语音 SDP 处理。
- 未向真实会话发送验收消息，双端发送与流式同步、修复后的实体手机语音仍待人工验收。
